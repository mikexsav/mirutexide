## Реальная интеграция

В `testing/test_integration.py` проверены:

- Java → Graph JSON → Java, отсутствие изменения исходника при roundtrip;
- поддерживаемая замена узла, компиляция, совпадение поведения;
- обнаружение намеренно изменённого вывода;
- реальная O(n²) диагностика с nodeId;
- ScopeShowcase: все базовые конструкции и JDK APIs из доступного PDF;
- MonolithDemo: 1430 строк, 101 метод, 918 узлов;
- по три сравнения на входах `5`, `0`, `-2` для обоих примеров;
- рефакторинг 100 private static методов в отдельный компонент, компиляция двух файлов и три сравнения;
- ZIP действительно содержит MonolithDemo.java и MonolithDemoComponent.java;
- одинаковые compile failures не дают successful comparison;
- бесконечный цикл останавливается по timeout;
- поток вывода ограничивается и не считается успешным сравнением;
- недоступность host filesystem и сети;
- heap <150 MiB, один доступный CPU, недоступная запись в root filesystem;
- runtime exception отражается в stderr/exit и корректно сравнивается;
- packages и несколько классов в одном source;
- отказ при неверном синтаксисе, поддельной топологии графа и некомпилируемом изменении узла.

Замер HTTP parse: ScopeShowcase 78 строк / 78 узлов — 0,028 с; MonolithDemo 1430 строк / 918 узлов — 0,075 с. Это отдельные локальные измерения, не гарантия времени на любой машине. JUnit дополнительно компилировал сгенерированные исходники javac --release 21.

## Браузер

Проверки выполняются через CUA во встроенном браузере, с настоящими HTTP-запросами. Подтверждены загрузка большого файла, Monaco, обе темы, диагностика 1052 сообщений с выдачей по 100, переход предупреждения к коду/графу, изменение `int pairs = 0;` → `int pairs = 0 + 0;` через компилятор, затем PASS трёх сравнений в интерфейсе.

Во время проверки выявлены и исправлены:

1. Несовместимые пути импорта локального Monaco 0.57.
2. Неконтрастный текст тёмной темы и слишком мелкий начальный масштаб графа.
3. Замена запущенного Spring JAR при повторной сборке: supervisor теперь запускает отдельную runtime-копию.
4. Порядок освобождения моделей Monaco DiffEditor при React StrictMode: введены фиксированные URI и сохранение моделей, проверки disposed model.

Финальный браузерный сценарий после исправления Monaco: рефакторинг прошёл проверки → применены два файла → ZIP скачан в Downloads и проверен на целостность → повторное сравнение в UI дало PASS на 5/0/3 → восстановлен снимок до рефакторинга, набор файлов снова содержит только исходник. До применения UI также сравнивал исходный и изменённый графом монолит на 5/0/-2.

Production frontend отдельно открыт из nginx: Monaco, граф и три реальных диагностических сообщения; ошибок консоли в этой вкладке не обнаружено. На ширине 390 px document clientWidth и scrollWidth равны 390: горизонтального переполнения страницы нет. Светлая/тёмная темы проверены. Скриншот рабочего экрана: qa/workspace.jpg.

Все три Dockerfile реально собраны, Maven source/tests компилировались на build-стадии engine. Дополнительно выполнена offline Maven-сборка в изолированном Java 21 контейнере с read-only кэшем зависимостей. Docker Compose проверялся на отдельном порту 5174, чтобы не конфликтовать с локальным приложением. После проверки временные Compose-сервисы остановлены; основной supervisor оставлен на 5173.

Выявлены и исправлены настройки Compose: bind socket должен ссылаться на /var/run/docker.sock внутри машины Docker daemon (для Colima это guest path); BusyBox frontend healthcheck использует явный IPv4 127.0.0.1 вместо localhost. Финальные проверки состояния всех сервисов — healthy.

## Ограничения проверки

PDF ссылается на отдельный технический документ, который не был приложен. Полнота относительно этого отсутствующего документа не проверялась. Внутренний CFG try/catch/finally и произвольная stateful декомпозиция не реализованы; их отсутствие явно указано в README и матрице требований. Совпадение на тестах не является формальным доказательством эквивалентности.

Предупреждения сборки: большой основной frontend chunk из-за Monaco; предупреждения Mockito/JDK о динамическом Java-agent в тестах; deprecation warning Starlette TestClient/httpx. Это не падения тестов. Полный аудит Java dependency CVE и нагрузочные испытания многопользовательского публичного сервиса не проводились.
