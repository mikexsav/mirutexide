# Mirutex IDE 2.0 — аккаунты и пространства

Дата: 25.10.2026. Опубликованная версия: https://193.233.247.61/.

## Что можно показать жюри

1. **Личный аккаунт.** Регистрация по логину, имени и паролю. Проекты разных пользователей разделены на сервере. Демо `user` без пароля по-прежнему открывается отдельной кнопкой.
2. **Кодовые пространства.** Несколько Java-проектов, названия, описания, поиск, копирование, архив и восстановление. Три стартовых шаблона и перенос старого локального проекта из браузера.
3. **Продолжение с другого устройства.** Сервер сохраняет текущий исходник, дополнительные файлы, baseline, до 20 снимков и тестовые входы. Автосохранение после ввода, ручное сохранение через Ctrl/⌘ S и резервный черновик в браузере. Сохраняются также пустые файлы и незавершённый Java-код.
4. **Защита двух вкладок.** Каждое сохранение проверяет номер версии. Если другая вкладка успела сохранить проект, сервер отвечает 409. Интерфейс предлагает открыть серверную версию или сохранить свой черновик отдельной копией. Новая версия не затирается молча.
5. **Ссылка на снимок.** Только текущий код и граф, без приватной истории, baseline и тестовых входов. Снимок не меняется вместе с проектом, действует 7 дней, ссылку можно отозвать. Получатель с аккаунтом может сделать собственную копию.
6. **Паспорт проверки.** Профиль → «Паспорт проверки» или палитра команд. JSON содержит SHA-256 всего набора исходников, фактические сведения о графе, диагностике, запуске и сравнении. Невыполненные и устаревшие проверки не становятся PASS. Отчёт не является математическим доказательством эквивалентности.
7. **Быстрый старт интерфейса.** Monaco и граф загружаются после экрана входа. Основной JavaScript стартовой страницы около 237 KB до gzip вместо загрузки всего редактора при входе.

## Проверка критериев AXENIX

| Критерий | Что подтверждает текущая версия | Материальная граница |
|---|---|---|
| Обязательный Java scope | ScopeShowcase, точный roundtrip, компиляция и запуски Java 21 | Внутренний CFG try/catch/finally пока атомарный |
| Сохранение поведения | Compile gate правок графа, проверки до применения рефакторинга, реальные stdout/stderr/exit code | Сценарии подтверждают только заданные входы |
| Диагностика и улучшения | 8 анализаторов с переходом к строке/узлу, перенос самостоятельных методов, diff и паспорт | Big O эвристический; произвольная stateful-декомпозиция не реализована |
| Понятный интерфейс | Настоящие символы блок-схемы, подсказки, палитра, темы, пространства, история и управление конфликтами | Локальные Java-подсказки без полноценного Java LSP |
| Реализация и демонстрация | Compose, HTTPS, серверное хранение, аккаунты, тесты, повторное открытие и экспорт проекта | Это демонстрационная платформа с одним SQLite-хранилищем и ограниченным Docker runner |

В предоставленном кейсе пять направлений оценки. Весов и полного отдельного технического документа нет. Максимальный балл или победа не присваиваются этим отчётом. Аккаунты и пространства — дополнительные возможности, а не замена обязательному Java-сценарию.

## Результаты проверок

- 19 Java JUnit.
- 42 API/SQLite/session теста. Включают межпользовательскую изоляцию, CSRF, срок сессии, хэши паролей, конфликт версий, публикацию/отзыв снимка, приватность старого главного файла и сохранение пустых/незавершённых черновиков.
- 40 frontend-тестов. Включают геометрию и маршрутизацию схемы, подсказки, поиск, отсутствие фиктивных результатов в паспорте, CSRF-запросы и восстановление пустого файла.
- 16 настоящих HTTP/Docker тестов локально: **74.13 s**.
- Те же 16 через опубликованный HTTPS после настройки health: **79.65 s**. Перед исправлением маршрута health был один конфигурационный сбой; после исправления полный повтор прошёл.

**117 разных тестов.** Повтор на сервере в сумму не добавлен. TypeScript и Vite production build прошли локально и при серверной Docker-сборке. `npm audit`: 0 известных уязвимостей. Lint без ошибок, с предупреждениями hooks. Крупный chunk Monaco остаётся предметом дальнейшего разделения.

Отдельно проверены настоящим HTTP: регистрация с Secure cookie, повторный вход, сохранение/открытие пространства, baseline и история, отказ анониму, конфликт, неизменяемый снимок, отзыв, архив и восстановление. Сессия и точное состояние проекта пережили перезапуск API. При финальном обновлении проверено сохранение после замены контейнеров; база вынесена в отдельный volume.

В браузере проверены регистрация, вход, создание проекта, изменение исходника, серверное автосохранение, повторное открытие во второй вкладке, компиляция, конфликт и сохранение копии, создание ссылки и просмотр графа.

## Хранение и доступ

- SQLite: `/data/mirutex.sqlite3` внутри API, именованный volume `mirutex_mirutex-data` на сервере. Пересборка образов не удаляет данные. `docker compose down -v` удаляет volume, поэтому для обычного обновления эта команда не используется.
- Пароль хранится как salted scrypt (N=2^17, r=8, p=1), исходный пароль не сохраняется. Сессии случайные, в базе только SHA-256 токена. Cookie HttpOnly, Secure на сервере, SameSite=Lax. Изменения требуют CSRF-токен и допустимый Origin.
- На аккаунт: 30 пространств с архивом, 20 MB текущих данных и опубликованных снимков, до 2 MB состояния пространства, до 20 файлов/512 KB исходников в одном проекте. Снимки истории занимают общий объём пространства.
- Java запускают зарегистрированные пользователи: до 120 условных запусков в час. Компиляция/запуск стоят одну единицу, сравнение двух версий — две на сценарий. Один запрос исполнения на аккаунт одновременно, общая очередь ограничена. Nginx дополнительно ограничивает частоту запросов.
- Восстановление пароля по email не подключено, это прямо указано при регистрации. Совместное редактирование в реальном времени и терминал с доступом к серверу не предоставляются.
- Для масштабирования и недоверенного многопользовательского production нужен отдельный worker/daemon для runner, полноценный процесс управления пользователями и резервированием. Текущий runner сохраняет ограничения CPU/RAM/времени/вывода и отключённую сеть.

Рекомендации для реализации: [OWASP Password Storage](https://cheatsheetseries.owasp.org/cheatsheets/Password_Storage_Cheat_Sheet.html), [Session Management](https://cheatsheetseries.owasp.org/cheatsheets/Session_Management_Cheat_Sheet.html), [CSRF Prevention](https://cheatsheetseries.owasp.org/cheatsheets/Cross-Site_Request_Forgery_Prevention_Cheat_Sheet.html).
